## Команды

- Unit-тесты: `./gradlew testDebugUnitTest`
- Все проверки гоняет CI: `.github/workflows/ci.yml`

## Правила кода
- Язык: Kotlin. Стиль — официальный Kotlin style guide.
- Backend проекта — Java/Spring, живёт в отдельном репозитории; его
  API-контракт здесь не менять, только использовать.
- Новая логика — обязательно с unit-тестами.
- Коммиты: короткий заголовок на английском в стиле
  `feat: ...` / `fix: ...` / `refactor: ...`, тело можно по-русски.

## Что НЕЛЬЗЯ делать
- Не трогать: `gradle/wrapper/`, `.github/`, файлы подписи и ключи.
- Не добавлять новые зависимости без явного указания в задаче.
- Не менять minSdk / targetSdk.
- Не коммитить секреты, токены, ключи — вообще никогда.
- Не отключать и не удалять существующие тесты, чтобы «починить» сборку.

## Определение готовности задачи
Задача считается сделанной, когда:
1. Код реализует ровно то, что описано в issue (не больше и не меньше).
2. `./run-checks.sh` проходит целиком.
3. На новую логику есть тесты.
