# Режим github-app: android-разработка на GitHub Actions

Схема после включения: **backend (приватный)** — Claude думает на
сервере, как сейчас (проверено, ~400 МБ). **android (публичный)** —
думает @claude на раннерах GitHub (7 ГБ RAM, минуты бесплатны без
лимита, gradle и lint можно гонять прямо там). **Сервер** — дирижёр
для обоих: очередь, автор-фильтр, 3 попытки, связка репо, Telegram.

## Как работает цикл android теперь

1. Оркестратор берёт issue из очереди (все защиты как раньше) и пишет
   в него: `@claude Реализуй... укажи в PR "AI-TASK: #N" и "Closes #N"`.
2. @claude на раннере GitHub пишет код и открывает PR.
3. Оркестратор находит PR по маркеру AI-TASK, ждёт CI.
4. CI красный → оркестратор пишет в PR `@claude CI упал, лог: ...` →
   App чинит в той же ветке → снова CI. Максимум 3 попытки.
5. CI зелёный → авто-ревью (лёгкий вызов на сервере) → пинг вам.
6. Межрепозиторные ошибки: агент оставляет комментарий
   `NEEDS-PARTNER: <описание>` — сервер сам заводит задачу в backend,
   ставит blocked и после починки возвращает задачу на перепроверку.
   Пинг-понг-защита работает как раньше (`CANNOT-FIX-HERE` → человеку).
7. Если PR или фикс не появились за APP_WAIT_MIN (45 мин) —
   `needs-human` и пинг в Telegram.

## Включение — 4 шага

**Шаг 1. Секрет в android-репо** (токен тот же, что на сервере):

```bash
gh secret set CLAUDE_CODE_OAUTH_TOKEN -R jack5505/mahalla-android
# вставить токен из `claude setup-token`
```

**Шаг 2. Workflow с защитой.** Положите `claude-android.yml` в
android-репо как `.github/workflows/claude.yml`. Если workflow от
@claude App там уже есть — оставьте один, но ОБЯЗАТЕЛЬНО перенесите
в него условие:

```yaml
if: |
  github.actor == 'jack5505' &&
  contains(github.event.comment.body, '@claude')
```

Репозиторий публичный: без этой строки любой прохожий сможет
командовать агентом и жечь вашу подписку. Оркестратор комментирует
от вашего аккаунта, поэтому фильтр он проходит.

**Шаг 3. Режим в конфиге android** (только android!):

```bash
sudoedit /etc/ai-dev-android.env
# добавить:
DEV_MODE=github-app
APP_WAIT_MIN=45
```

В `/etc/ai-dev-backend.env` ничего не менять (там остаётся local).

**Шаг 4. Разрешить сборки в CLAUDE.md android-репо.** Раздел про
запрет gradle замените на:

```markdown
## Окружение
- Ты работаешь на CI-раннере GitHub: JDK и Android SDK доступны,
  ./gradlew запускать МОЖНО и нужно (сборка, тесты, lint) до пуша.
```

И обновите оркестратор на сервере:

```bash
sudo cp orchestrator-ci.sh /opt/ai-dev/orchestrator-ci.sh
```

## Что важно понимать

- Подписка Claude всё равно одна на всё: App тратит те же лимиты,
  что и сервер. Переезд разгружает память сервера, а не лимиты.
- Минуты Actions: android публичный — безлимит; в backend ничего не
  меняется.
- Оркестратор опрашивает GitHub раз в 60 секунд — реакция на события
  App с задержкой до минуты, это нормально.
- Ход «мышления» агента теперь виден в самом PR/issue (комментарии
  App) и во вкладке Actions android-репо, а не в journalctl.
